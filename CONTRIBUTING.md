# Contributing to Slaython

Thanks for helping. Slaython is small on purpose: one stdlib-only Python
package, a word list, and a few tools around it.

## Set up

```sh
git clone https://github.com/memoliertorerr/Slaython
cd Slaython
pip install -e .
python -m unittest discover -s tests -t .
```

Python 3.10 or newer. No other dependencies, except `ipykernel` if you work
on the Jupyter kernel.

## Where things live

| Path | What it is |
|---|---|
| `slaython/keywords.py` | Every word and what it maps to. Start here. |
| `slaython/transpiler.py` | Word-level translation, keeps line numbers |
| `slaython/compiler.py` | Syntax-tree pass for `shoot n:` and `\|>` |
| `slaython/runner.py`, `cli.py`, `repl.py` | Running code, the command line, the REPL |
| `slaython/*.py` (others) | One file per tool: `testing`, `glowup`, `learn`, `build`, `fmt`, `lint`, `kernel`, ... |
| `editors/vscode/` | VS Code extension. Most files are generated by `tools/gen_vscode_grammar.py` |
| `playground/`, `docs/` | The website, built by `tools/build_playground.py` |
| `examples/` | Example programs (they run in the tests) |

## Adding or changing a word

1. Edit `slaython/keywords.py`. Each entry has the slang, the Python it
   stands for, what the slang means, and why it fits.
2. Run `python tools/gen_vscode_grammar.py` to update the VS Code files.
3. Run the tests and fix any example that used the old word
   (`slaython glowup` won't do it for you; it only swaps Python keywords).

Want a new word but not sure? Open an issue with the "New slang" template.

## Before you open a pull request

- `python -m unittest discover -s tests -t .` passes
- `python tools/gen_vscode_grammar.py --check` passes
- New behaviour has a test, and the README or `docs/` says how to use it
- No new dependencies in the `slaython` package (the playground loads it in
  the browser, where only the standard library exists)

## Releasing (maintainers)

Bump `__version__` in `slaython/__init__.py`, add a section to
`CHANGELOG.md`, push, then publish a GitHub release tagged `v<version>`.
The `publish` workflow uploads to PyPI and the `vscode` workflow publishes
the extension.
